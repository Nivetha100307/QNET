# QNetSecure API Contract — Module 3: Quantum Key Management

This document specifies the complete API contract and architecture for Module 3 of **QNetSecure (AI-Enabled E91 Quantum Communication Network)**.

## Base URL
```
http://localhost:8000/api/v1
```

---

## Overview & Workflow

Module 3 handles basis reconciliation, key sifting, raw shared secret key generation, and database persistence for E91 Quantum Key Distribution sessions.

```
ACTIVE SESSION ➔ LOAD MEASUREMENTS ➔ BASIS RECONCILIATION ➔ FIND MATCHING BASES ➔ DISCARD NON-MATCHING ➔ GENERATE ALICE KEY ➔ GENERATE BOB KEY ➔ GENERATE SHARED SECRET ➔ PERSIST & RETURN
```

---

## Business Rules

1. **Session Existence & Status**: The target session must exist and be in `ACTIVE` state.
2. **Measurement Prerequisite**: Quantum measurements generated by Module 2 must exist.
3. **Basis Reconciliation**: Only matching measurement bases (\(a_i == b_i\)) contribute to the key.
4. **Key Sifting**: Alice's and Bob's sifted keys must be equal in length.
5. **Shared Secret Generation**: The raw shared secret key is constructed exclusively from sifted bits at matching indices.

---

## Database Schema (`quantum_keys`)

| Column Name | Type | Constraints | Description |
| :--- | :--- | :--- | :--- |
| `id` | INTEGER | Primary Key, Auto-increment | Internal DB ID |
| `session_uuid` | VARCHAR(36) | Unique, Index, Not Null | Session UUID string |
| `key_length` | INTEGER | Not Null, Default: 0 | Length of the generated key in bits |
| `matching_indexes` | JSON | Not Null, Default: `[]` | List of 0-based matching basis indices |
| `alice_key` | TEXT | Not Null, Default: `""` | Alice's sifted bit string |
| `bob_key` | TEXT | Not Null, Default: `""` | Bob's sifted bit string |
| `shared_key` | TEXT | Not Null, Default: `""` | Reconciled raw shared secret key string |
| `generation_status` | VARCHAR(30) | Not Null, Default: `"STARTED"` | Generation state (`GENERATED`, `FAILED`) |
| `created_at` | DATETIME | Not Null, Default: UTC Now | Generation timestamp |

## REST API Endpoints

### 1. Generate Quantum Key
**`POST /key/generate`**

Executes basis reconciliation, sifting, and raw shared key generation for an active session.

#### Request Body (`KeyGenerationRequest`)
```json
{
  "session_uuid": "4f9d2c18-9104-4b5c-a81d-e59fa20b12cd"
}
```

#### Success Response (`200 OK` — `KeyGenerationResponse`)
```json
{
  "session_uuid": "4f9d2c18-9104-4b5c-a81d-e59fa20b12cd",
  "generation_status": "GENERATED",
  "matching_indexes": [0, 2, 3, 5, 7],
  "alice_key": "10110101",
  "bob_key": "10110101",
  "shared_key": "10110101",
  "key_length": 8,
  "created_at": "2026-07-30T00:15:00.000Z"
}
```

#### Error Response (`400 Bad Request`)
```json
{
  "detail": "Cannot generate quantum key for session '...' in state 'READY'. Session must be in 'ACTIVE' state."
}
```

---

### 2. Get Full Key Details
**`GET /key/{session_uuid}`**

#### Success Response (`200 OK`)
Returns full `KeyGenerationResponse` object.

---

### 3. Get Lightweight Key Status
**`GET /key/status/{session_uuid}`**

#### Success Response (`200 OK` — `KeyStatusResponse`)
```json
{
  "session_uuid": "4f9d2c18-9104-4b5c-a81d-e59fa20b12cd",
  "generation_status": "GENERATED",
  "key_length": 512
}
```

---

### 4. Get Raw Shared Secret Key
**`GET /key/shared/{session_uuid}`**

#### Success Response (`200 OK` — `SharedKeyResponse`)
```json
{
  "session_uuid": "4f9d2c18-9104-4b5c-a81d-e59fa20b12cd",
  "shared_key": "10110101...",
  "key_length": 512
}
```
